# 产品规划

## 为谁解决什么问题

面向经常把电脑上网址传到手机的开发者、产品人员和知识工作者。高频场景是在编辑器或文档里选中 HTTP(S) 地址，立即扫码，无需开二维码网站。

价值假设：一部分用户不使用 Raycast，希望独立、小巧、无账号、内容不离开本机的工具。已有同类，不宣称市场空白。先验证触发是否稳定、是否真的节省操作，再决定长期维护。

## 第一版

Swift + AppKit 菜单栏应用，CoreImage 编码，系统 Services 接收文本，手动输入和显式剪贴板兜底。输出黑白二维码、原文，Esc 关闭。服务快捷键由 macOS 管理，与全局读取任意应用选区不同。

不做：扫描、持久化自动历史、分类、搜索、同步、账户、AI、美化 Logo、批量、自动浮标、短链、自动打开 URL、全局辅助功能抓取。

## 验收标准

1. 公共 URL、含查询参数/片段、中文和换行可编码，并用 Vision 解码得到原文。
2. nil、空文本、纯空白、非文本及超过上限的输入给出可理解提示。
3. 输出有至少四模块白边；按整数倍渲染，不拉伸。
4. 点击生成后可见二维码和原文；Esc 关闭后可再次从菜单栏打开。
5. 至少 TextEdit 和一款已安装编辑器验证 Services；不支持的应用明确记录，禁止声称全应用通用。
6. 不进行网络调用，仅成功生成进入本次运行的 10 条最近列表，用户主动收藏才持久化，不读取无关内容；不要求辅助功能权限。

## 新增：最近生成与收藏

用户已要求加入轻量历史/收藏。最近生成仅内存最近 10 条，重复原文前移、可一键清空、退出清空；收藏必须主动点击、命名，可重新生成与删除，保存在用户 Application Support 的本地明文文件。提醒 token/临时参数风险，不检测删除或改写参数，不记录 URL 到日志。生成失败的输入不加入最近列表。不做分类、搜索、云同步。

## 待验证

Services 的发现/安装位置、来源应用文本类型、编辑器兼容、键盘快捷键冲突、失焦体验、深色模式与不同屏幕倍率、手机实际扫码、非 ASCII 二维码在不同手机上的编码解释、Intel 与旧 macOS。

## 内容与个人 IP

以「认真做小工具的开发者」记录过程：真实痛点 → 竞品与取舍 → 第一版 → 用户反馈。每次有真实改进再发公众号，不为日更添加无价值功能。首篇可讲为什么已有竞品仍做独立工具；发布时隐去公司内部 URL 和桌面隐私。

## 视觉方向

参照用户描述的 Apple 原生偏好设置风格：浅灰磨砂、居中标题、等宽图标导航、选中白色卡片与系统蓝、圆角控件和均衡留白。保持 macOS 桌面 App，不做手机外框。生成/最近/收藏共享布局。二维码自身不透明纯白，黑色模块和四模块白边不受磨砂影响。不从参考图扩展出开机启动或隐藏状态栏需求。
